# EIP-0045 development checkpoint — 5 November 2026

Nine targeted local fixture tests now pass for retaining source inputs through
consumer execution and checking them again before returning an owned result.
All nine ran: none failed or was ignored or skipped. Their captured execution
results and source bindings received independent review.

The tests use synthetic files with the compiled implementation. They exercise
fixed source roles, cache inventories and payloads, case/path aliases,
coordinated identity changes, source drift and error propagation. They also
check that a failed final physical check or a late source change prevents an
owned result from being returned. They do not establish that arbitrary
consumer side effects can be rolled back.

The same source snapshot passed a non-test Rust library check and compiled
as a library test binary with Rust 1.89.0, locked offline dependencies and thirteen selected
features. This checkpoint covers those nine selected tests on that binary;
the complete test suite and other feature combinations remain unqualified.
Checks that Rust rejects reuse, escaping borrows or unsupported trait
implementations are still pending.

Since the [28 October update](2026-10-28.md), the work has also reached three
targeted Rust/JVM comparisons. Changed terminal kind, parameter and control ID
each produced the expected rejection and byte-identical records between the
two implementations. The [4 November note](2026-11-04.md) gives their scope
and the separate comparisons against expected results.

These are local validation results. The new native sources have not yet been
added to this repository, so its current sources do not provide a complete
reproduction package for these results. No new proof was generated by the
nine fixture tests.

The next B4 target remains eleven ordered positive cases, 254 independently
reconstructed negative materialization identities and 508 Rust/JVM results in
one closed archive. Formal campaign credit is still 0/508. B5–B8 remain open,
including measured consensus costs, the authenticated activation transition,
fresh independent reproduction and remaining node/admission work.

Both the [EIP proposal](https://github.com/ergoplatform/eips/pull/103) and the
[SigmaState implementation PR](https://github.com/ergoplatform/sigmastate-interpreter/pull/1116)
remain open and unmerged. No profile has been activated on Ergo.
