# EIP-0045 development checkpoint — 6 November 2026

Local Rust compiler checks now cover six usage examples for the API that owns
retained source inputs. A permitted conversion from a physical capture to a
source owner, followed by view access and an input recheck, compiles. Five
misuse examples are rejected.

Four of these diagnostics were newly executed with Rust 1.89.0, locked offline
dependencies and thirteen selected features. They complete the focused set
alongside two previously qualified compiler controls; those two controls were
referenced from their original records rather than run again.

| Usage example | Compiler outcome | Evidence in this checkpoint |
| --- | --- | --- |
| Permitted capture conversion, view access and input recheck | Compiles | Previously qualified control |
| Reuse the capture after consuming it | Rejected: use of a moved value (`E0382`) | Previously qualified control |
| A borrowed byte slice escapes the view callback | Rejected: lifetime constraint | Newly executed |
| Require `Clone` on the source owner | Rejected: unsupported trait bound (`E0277`) | Newly executed |
| Require `serde::Serialize` on the source owner | Rejected: unsupported trait bound (`E0277`) | Newly executed |
| Require `serde::Deserialize` on the source owner | Rejected: unsupported trait bound (`E0277`) | Newly executed |

Each new negative example produced one primary compiler error and a failed
build as expected. These are compile-time checks: no example body was run.
They test specific API usage constraints, not cryptographic proof validity or
the behavior of every possible consumer.

Since the [28 October checkpoint](2026-10-28.md), local validation has also
reached three targeted Rust/JVM comparisons and nine retained-input fixture
tests. Changed terminal kind, parameter and control ID produced matching
rejections with byte-identical records in Rust and the JVM, as described in
the [4 November report](2026-11-04.md). All nine fixture tests executed and
passed, covering source roles, cache integrity and checks after a consumer
finishes; the [5 November report](2026-11-05.md) records their scope and limits.

The new native sources remain unpublished. The current repository therefore
does not provide a complete reproduction package for these local results.
No new cryptographic proof was generated by the compiler checks or the nine
fixture tests.

The next development step is to compile the latest retained-input catalogue
and run its focused tests. B4 still requires eleven ordered positive cases,

508 Rust/JVM results in one closed archive. Formal campaign credit remains
0/508. Measured consensus costs, the authenticated activation transition,
