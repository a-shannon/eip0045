# EIP-0045 development checkpoint — 4 November 2026

Three targeted local tests now agree across Rust and JVM on rejecting changed
terminal metadata. The cases change the kind, parameter and control ID.

The [29 October diagnostic](2026-10-29.md) ended before a neutral input
existed. Since then, a bounded preparation run completed, replayed the
retained proof and produced the kind-test input. A native publisher then
created the parameter and control-ID inputs. Their canonical descriptors,
512-byte subjects and seven contexts per root received independent checks.
No new proof was generated for these two additions.

Rust and JVM read separate copies of each neutral input. All three cases
returned the expected `terminal-metadata-mismatch` rejection at
`terminal-metadata-binding`, with byte-identical 448-byte records within
each pair.

| Changed field | Targeted Rust/JVM result | Separate expected-result check |
| --- | --- | --- |
| Kind | Same rejection and bytes | Matched the negative-plan recipe |
| Parameter | Same rejection and bytes | Matched the negative-plan recipe |
| Control ID | Same rejection and bytes | Matched the negative-plan recipe |

The captured verifier results received independent review. The separate
supplied-byte checks compared the actual Rust/JVM records before loading the
expected test recipe. This gives developers a concrete interoperability
checkpoint: these malformed inputs reach the same failure boundary in both
implementations.

These are local results. The native additions used for the new inputs and
runs have not yet been added to this repository, so the published sources
do not yet form a complete reproduction package for this checkpoint.
